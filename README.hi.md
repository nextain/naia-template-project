# Naia ADK

**AI कोडिंग एजेंटों के काम करने के लिए पहले से सजाया हुआ वर्कस्पेस ढाँचा।**

जब Claude Code या Codex जैसे AI कोडिंग टूल इस्तेमाल करते हैं, तो हर टूल अपनी नियम फ़ाइलें
अलग-अलग जगह रखता है, और «क्या यह दस्तावेज़ प्रकाशित किया जा सकता है?» या «स्किल कहाँ जाएँगे?»
जैसे सवालों के जवाब जुगाड़ से दिए जाते हैं। Naia ADK यह ढाँचा पहले से बिछा देता है। जैसे नए
लैपटॉप पर डेवलपमेंट माहौल सेट करते हैं, वैसे ही यह AI एजेंट को शुरुआत के लिए सजी हुई मेज़ देता
है। साथ में एक डैशबोर्ड भी है जिससे वर्कस्पेस की हालत एक नज़र में दिखती है।

## 5 मिनट में चालू करें

आपको **Node 22+** और **pnpm 9+** चाहिए।

```bash
pnpm install    # वर्कस्पेस की डिपेंडेंसी स्थापित करें
pnpm dev        # API सर्वर (:3141) और डैशबोर्ड (:3142) एक साथ चलाएँ
```

डैशबोर्ड देखने के लिए ब्राउज़र में `http://localhost:3142` खोलें। तीन चीज़ें तुरंत दिखती हैं:

- **वर्कस्पेस** — प्रोजेक्ट और सबमॉड्यूल, फ़ाइल ट्री, और हर आइटम का
  प्रकटीकरण स्तर।
- **स्किल कैटलॉग** — इस वर्कस्पेस में पंजीकृत स्किलों की सूची और उनकी
  सामग्री।
- **सेटिंग / निगरानी** — सर्वर कॉन्फ़िगरेशन, क्लाइंट स्थिति, डेटा डायरेक्टरी।

डैशबोर्ड `/api/*` अनुरोधों को पोर्ट 3141 पर चल रहे API सर्वर को भेज देता है। सिर्फ़ एक चलाने के
लिए `pnpm dev:server` (→ 3141) या `pnpm dev:dashboard` (→ 3142) इस्तेमाल करें। लॉन्चर स्क्रिप्ट
`./start.sh` (Linux/macOS) और `start.bat` (Windows) दोनों `pnpm dev` ही चलाते हैं। सर्वर CLI
`--port`, `--host` और `--root` लेता है; मिसाल के तौर पर दूसरे वर्कस्पेस की ओर इशारा करने के लिए
`pnpm serve -- --root /path/to/workspace` लिखें।

## अंदर क्या है

### वर्कस्पेस ढाँचा

यह AI एजेंट को तय जगहों वाली डायरेक्टरियों का सेट देता है, ताकि वह तुरंत काम शुरू कर सके।
AI वाला संदर्भ `.agents/` में रहता है (अंग्रेज़ी, JSON/YAML), और इंसानों के पढ़ने लायक दर्पण
`.users/` में रहता है (कोरियाई, Markdown)। यह दर्पण आंशिक है, पूरी नकल नहीं — इसमें वे दस्तावेज़
हैं जो इंसान को पढ़ने चाहिए (मसलन स्किल `.agents/skills/` में प्रमाणिक हैं, और उनमें से कुछ ही
`.users/skills/` में दिखते हैं)। स्किल, डेटा और प्रोजेक्ट सबकी तय जगह है, इसलिए चाहे जो टूल
खोले, वर्कस्पेस एक जैसा दिखता है।

### डैशबोर्ड और API

वर्कस्पेस को आँखों से सँभालने वाला Next.js डैशबोर्ड, जिसके पीछे Fastify API सर्वर खड़ा है। API
वर्कस्पेस मेटाडेटा (`/api/workspace`), स्किल कैटलॉग (`/api/skills`), फ़ाइल पढ़ना-लिखना
(`/api/files`), और फ़ाइल बदलावों को लाइव सुनाने वाला WebSocket (`/api/ws`) देता है। इस API की
बदौलत डैशबोर्ड के अलावा दूसरे प्रोग्राम भी वर्कस्पेस तक पहुँच सकते हैं।

### स्किल प्रणाली

दोहराए जाने वाले काम दोबारा इस्तेमाल लायक स्किलों में बाँध दिए जाते हैं। हर स्किल एक ही `SKILL.md`
से परिभाषित होता है, और API सर्वर `skills/` को स्कैन करके कैटलॉग बनाता है। अगर एक भी स्किल
फ़ॉर्मैट तोड़े तो पूरा कैटलॉग त्रुटि देता है (fail-closed): टूटे स्किल को चुपचाप छोड़कर बाकी
परोसने के बजाय ऑपरेटर को वहीं ठीक करने पर मजबूर किया जाता है। अधूरा कैटलॉग गलती से शिप न हो,
इसलिए यह सोच-समझकर चुना गया रास्ता है।

### नियम और न्यूनतम अभिशासन

अकेले इस्तेमाल होने वाले वर्कस्पेस में भी कम से कम नियम चाहिए, जैसे ही AI और ऑटोमेशन उसे छुएँ।
Naia ADK `read`, `write`, `execute` और `publish` को अलग-अलग सरोकार मानकर बाँटता है, और हर
दस्तावेज़ पर प्रकटीकरण स्तर लगाता है। मुश्किल से वापस होने वाले काम — प्रोडक्शन बदलाव, सीक्रेट
सँभालना, सार्वजनिक दावे — आम लोकल एडिट से अलग करके अनुमोदन गेट से गुज़ारे जाते हैं।

प्रकटीकरण के चार स्तर हैं। `public` सार्वजनिक साइट या ओपन-सोर्स रेपो पर ज्यों का त्यों जा सकता
है; `controlled` समीक्षा के बाद बाहर साझा किया जा सकता है; `internal` वर्कस्पेस के अंदर रहता है;
`confidential` संवेदनशील सामग्री ढकता है जैसे अनुबंध, क्रेडेंशियल और निजी डेटा। क्रेडेंशियल
आमतौर पर git के बाहर रहते हैं, पर स्तर के हिसाब से फिर भी `confidential` हैं।

> **इस रिलीज़ में सत्र-अनुबंध प्रवर्तन बंद है।** `.claude/no-harness` मार्कर कमिट किया हुआ है,
> इसलिए सत्र-अनुबंध गेट कुछ नहीं रोकता। इसे चालू करने पर बिना अनुबंध वाला सत्र हर बदलावकारी शेल
> कमांड पर रुकेगा — `npm test` समेत — यानी नया क्लोन अपना टेस्ट सूट तक नहीं चला पाएगा। फ़ाइल
> संपादन पथ इसी वजह से खोला गया था; शेल पथ को अभी वैसा बर्ताव नहीं मिला है। फ़ोर्स-पुश,
> विनाशकारी git, डिप्लॉय और बाहरी संदेश गार्ड इससे अछूते हैं और चलते रहते हैं। प्रगति
> [#34](https://github.com/nextain/naia-template-project/issues/34) में ट्रैक होती है, विवरण
> `.claude/no-harness` में है। `AGENTS.md` का सत्र सीमा वाला भाग इरादे के मुताबिक डिज़ाइन बताता
> है, मौजूदा रनटाइम बर्ताव नहीं।

### LLM अडैप्टर (naia-anyllm)

जिन फ़ीचरों को LLM तक पहुँचना होता है, उनके लिए `naia-anyllm` अडैप्टर अंदर बना है। यह
[any-llm](https://github.com/nextain/any-llm) गेटवे से जुड़ता है, या OpenAI, Anthropic और Google
जैसे प्रदाताओं से सीधे जुड़ता है। डिफ़ॉल्ट Naia खाता है: [naia.nextain.io](https://naia.nextain.io)
से जारी की गई कुंजी `NAIA_KEY` एनवायरनमेंट चर में डालें और खाते के क्रेडिट तुरंत इस्तेमाल करें।
कुंजी न हो तो किसी भी भुगतान वाले कॉल से पहले त्रुटि देता है। प्रदाता या मॉडल बदलने के लिए
[`.agents/context/llm-config.yaml.example`](.agents/context/llm-config.yaml.example) की नकल
करके इस्तेमाल करें, और API कुंजियाँ कॉन्फ़िगरेशन फ़ाइल में नहीं, एनवायरनमेंट चर या OS के कीस्टोर
में रखें। `naia-settings/llm.json` सिर्फ़ `apiKeyRef: "NAIA_KEY"` दर्ज करता है, कुंजी का मान
कभी नहीं। निजी फ़ोर्क को लंबे समय का बैकअप चाहिए तो `data-private/key/` में age-एन्क्रिप्टेड
वॉल्ट इस्तेमाल करें (देखें [`.env.example`](.env.example))।

समर्थित मॉडल और मौजूदा कीमतें देखने, और लंबे PDF अनुवादने के लिए `translate-doc` स्किल
इस्तेमाल करें। मॉडल-कीमत पूछताछ बिना कुंजी चलती है; अनुवाद पहले अनुमानित लागत बताता है और रुकी
जगह से फिर शुरू हो सकता है।

## ऐसे क्यों बनाया गया

### फ़ॉर्मैट ही अनुबंध है

Naia ADK का दिल कोई खास टूल नहीं, **फ़ॉर्मैट** है। डायरेक्टरी खाका (`.agents/`, `.users/`,
`skills/`, `data-*/`) और फ़ाइल स्कीमा (`agents-rules.json`, `SKILL.md`) पक्का करार हैं, और जो
भी टूल यह करार पढ़ सके वही वर्कस्पेस खा सकता है। Claude Code, opencode, Codex और naia-agent
एक-दूसरे का कोड डाले बिना वही वर्कस्पेस पढ़ते हैं। इसलिए टूल बदलें या कई मिलाकर चलाएँ,
वर्कस्पेस चलता रहता है।

नियम प्रवर्तन भी टूल-निरपेक्ष है। होस्ट-निष्पक्ष कोर (`.agents/hooks/core/`) और नीतियाँ
(`.agents/hooks/policies/`) उन्हीं नियमों से Claude Code हुक और pi एक्सटेंशन दोनों चलाते हैं।

### टीम बनने से पहले निजी आधार

Naia ADK सख़्ती से एकल-उपयोगकर्ता, निजी इस्तेमाल के लिए है। कंपनी संगठन-चार्ट, टेनेंट नियम और
प्रत्यायोजित अनुमोदन शृंखलाएँ ऊपरी परत का काम हैं। यह आपको एक ही जगह देता है — वर्कस्पेस के टीम
या कंपनी आकार में बढ़ने से पहले संदर्भ अनुशासन कहाँ लिखना है, यह पहले से तय करने की जगह।

जब टीम सहयोग और साझा ज्ञान चाहिए हो, तो
[Naia Business ADK](https://nextain.io/adk) तक विस्तार करें। यह विस्तार आधार-रेखा को संपत्ति-,
प्रक्रिया- और अनुमति-अभिशासन तक फैलाता है, और टीम स्वामित्व व प्रत्यायोजित अनुमोदन जोड़ता है।

### फ़ोर्क शृंखला

Naia ADK फ़ोर्क करके अपना बनाने के लिए है। व्यक्ति `naia-adk` सीधे फ़ोर्क करते हैं; संगठन
`naia-business-adk` से होते हुए कंपनी और सदस्य वर्कस्पेस बनाते हैं।

```
naia-adk                  ← निजी आधार (सार्वजनिक, Apache 2.0)
  └── {org}-adk           ← संगठन फ़ोर्क: कंपनी डेटा + बिज़नेस सबमॉड्यूल
        └── {user}-adk    ← निजी फ़ोर्क: निजी डेटा + प्रोजेक्ट सबमॉड्यूल
```

Nextain की असली शृंखला `naia-adk → naia-business-adk → nextain-adk → alpha-adk` चलती है।

## संरचना

रेपो रनटाइम कोड (`packages/`), नियम और संदर्भ (`.agents/`, `.users/`), स्किल (`skills/`,
`.agents/skills/`), और हर फ़ोर्क द्वारा भरी जाने वाली डेटा डायरेक्टरियों में बँटा है।

| डायरेक्टरी | प्रयोजन |
|-----------|---------|
| `.agents/` | AI वाला संदर्भ (अंग्रेज़ी, JSON/YAML) — नियमों का इकलौता सत्य स्रोत |
| `.users/` | इंसानों के पढ़ने लायक दर्पण (कोरियाई, Markdown) |
| `.claude/` | Claude Code कॉन्फ़िगरेशन, हुक, स्किल सिमलिंक |
| `skills/` | परिचालन/रनटाइम स्किल (डैशबोर्ड API द्वारा परोसे जाते हैं) |
| `scripts/` | उपयोगिता स्क्रिप्ट |
| `templates/` | दस्तावेज़ टेम्पलेट |
| `docs/` | आर्किटेक्चर दस्तावेज़, डिज़ाइन विशिष्टियाँ |
| `packages/` | रनटाइम पैकेज (pnpm वर्कस्पेस) |

### रनटाइम पैकेज (packages/, कुल 10)

तीन असल में चलने वाले प्रोग्राम हैं; बाकी फ़ॉर्मैट और विशिष्टियाँ बताने वाले पतले पैकेज हैं।

- `core` — वर्कस्पेस और स्किल पार्स करने वाला इंजन।
- `server` — Fastify वाला REST/WebSocket API।
- `dashboard` — Next.js डैशबोर्ड UI।
- `skill-spec` — टूल-निरपेक्ष स्किल फ़ॉर्मैट अनुबंध (`SkillDescriptor`, `SkillLoader`)।
- `skills-builtin` — सामान्य स्किल कैटलॉग।
- `openclaw-compat` — OpenClaw स्किलों को naia फ़ॉर्मैट में बदलने वाला टूल।
- `persona` — सिस्टम-प्रॉम्प्ट परिपाटी विशिष्टि।
- `process` — वर्कफ़्लो पैटर्न विशिष्टि (समीक्षा → निर्णय → निष्पादन, मुद्दा-चालित
  विकास वगैरह)।
- `naia-anyllm` — any-llm गेटवे / प्रत्यक्ष-प्रदाता LLM अडैप्टर।
- `artifacts-spec` — अनुमति (RBAC) और विकास जीवनचक्र (SDLC) कलाकृतियों का मानक स्कीमा। 15
  तरह की कलाकृतियाँ JSON Schema में परिभाषित करता है और हर एक के लिए बताता है कि इंस्टेंस
  git-ट्रैक्ड है या सत्र-सीमित।

### डेटा डायरेक्टरी (gitignored, हर फ़ोर्क में भरी जाती हैं)

ये चार कभी कमिट नहीं होतीं। जो रेपो फ़ोर्क करे वह अपना डेटा डाले।

| डायरेक्टरी | दायरा | सामग्री |
|-----------|-------|---------|
| `data-company/` | कंपनी | कंपनी-भर के दस्तावेज़, साझा संसाधन |
| `data-teams/` | टीम | टीम दस्तावेज़ (रणनीति, लेखा वगैरह) |
| `data-private/` | निजी | निजी डेटा, env फ़ाइलें, निजी दस्तावेज़ |
| `projects/` | निजी | प्रोजेक्ट रेपो (सबमॉड्यूल) |

### दो स्किल वृक्ष

स्किल दो जगह रहते हैं, दो अलग पक्ष उन्हें खाते हैं।

- `.agents/skills/` — AI सहायता और वर्कफ़्लो स्किल। Claude Code इन्हें `.claude/skills/`
  सिमलिंक से इस्तेमाल करता है। समीक्षा (`review-pass`), सत्यापन (`verify-implementation`),
  वर्कट्री विलय (`merge-worktree`), दस्तावेज़ निष्कर्षण (`read-doc`), पेटेंट/कॉपीराइट/वेतन जैसे
  व्यावसायिक स्किल, और `finetune-persona`, `secret-vault`, `youtube-upload` वगैरह शामिल हैं।
- `skills/` — परिचालन/रनटाइम स्किल। API सर्वर `skills/**/SKILL.md` स्कैन करके डैशबोर्ड को
  परोसता है। इनमें ईमेल/SMS/सूचना भेजना, चैनल प्रबंधन, सेवा व वेब निगरानी, और दस्तावेज़ निर्माण
  हैं; `skills/business/` में संगठन वाले स्किल हैं जैसे `press-release`।

सबसे सही सूची डैशबोर्ड का स्किल कैटलॉग है। पाठ वाली तालिका
[AGENTS.en.md](AGENTS.en.md#skills) में भी रखी है।

## शुरुआत

### निजी

1. `naia-adk` को अपने खाते में फ़ोर्क करें (हो सके तो प्राइवेट)।
2. क्लोन करें: `git clone https://github.com/YOUR-USER/your-adk.git && cd your-adk`
3. अपस्ट्रीम जोड़ें: `git remote add upstream https://github.com/nextain/naia-template-project.git`
4. डेटा डायरेक्टरी बनाएँ: `mkdir -p data-private projects`
5. प्रोजेक्ट जोड़ें, `.agents/` कॉन्फ़िगर करें, और काम शुरू करें।
6. Naia खाता संसाधन इस्तेमाल करें तो `NAIA_KEY` एनवायरनमेंट चर में सेट करें।
7. समय-समय पर सिंक करें: `git fetch upstream && git merge upstream/main`

### कंपनी

1. `naia-business-adk` की पहुँच के लिए [संपर्क करें](https://nextain.io/contact)।
2. `naia-business-adk` को संगठन खाते में प्राइवेट फ़ोर्क करके क्लोन करें।
3. अपस्ट्रीम जोड़ें: `git remote add upstream https://github.com/nextain/naia-business-adk.git`
4. कंपनी डेटा और प्रोजेक्ट सबमॉड्यूल भरें: `mkdir -p data-company projects`,
   `git submodule add <repo> projects/<name>`
5. हर सदस्य संगठन ADK को फिर फ़ोर्क करके निजी वर्कस्पेस बनाए।

### Naia Shell एकीकरण (वैकल्पिक)

[Naia Shell](https://github.com/nextain/naia-shell) डेस्कटॉप ऐप इस्तेमाल करते हैं तो उसके
वर्कस्पेस पथ को अपनी ADK डायरेक्टरी पर इंगित करें। स्किल और डेटा API से परोसे जाते हैं।

संदर्भ, साझा कलाकृतियाँ) अंग्रेज़ी में रखें। पूरी प्रक्रिया और नियमों के लिए
