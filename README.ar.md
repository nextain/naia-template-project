# Naia ADK

**هيكل مساحة عمل مُرتَّب مسبقًا ليعمل فيه وكلاء الترميز بالذكاء الاصطناعي.**

عند استخدام أدوات الترميز بالذكاء الاصطناعي مثل Claude Code أو Codex، يحتفظ كل أداة بملفات
القواعد في مكان مختلف، وأسئلة مثل «هل يمكن نشر هذا المستند؟» أو «أين توضع المهارات؟» تُجاب
عليها ارتجاليًا. يجهّز Naia ADK هذا الهيكل مسبقًا. فكما تُهيّئ بيئة التطوير على حاسوب محمول
جديد، فإنه يسلّم لوكيل الذكاء الاصطناعي مكتبًا مرتبًا ليبدأ منه. كما يتضمن لوحة تحكم لرؤية
حالة مساحة العمل بنظرة واحدة.

## التشغيل خلال 5 دقائق

تحتاج إلى **Node 22+** و**pnpm 9+**.

```bash
pnpm install    # تثبيت اعتماديات مساحة العمل
pnpm dev        # تشغيل خادم API ‏(:3141) ولوحة التحكم (:3142) معًا
```

افتح `http://localhost:3142` في المتصفح لرؤية لوحة التحكم. ثلاثة أشياء تظهر فورًا:

- **مساحة العمل** — المشاريع والوحدات الفرعية، وشجرة الملفات، ومستوى الإفصاح لكل عنصر.
- **فهرس المهارات** — قائمة المهارات المسجلة في مساحة العمل هذه ومحتواها.
- **الإعدادات / المراقبة** — إعدادات الخادم، وحالة العملاء، وأدلة البيانات.

تُحوّل لوحة التحكم طلبات `/api/*` إلى خادم API على المنفذ 3141. لتشغيل أحدهما فقط استخدم
`pnpm dev:server` (→ 3141) أو `pnpm dev:dashboard` (→ 3142). سكربتا الإطلاق `./start.sh`
(Linux/macOS) و`start.bat` (Windows) يشغّلان `pnpm dev` معًا. يقبل CLI الخاص بالخادم
`--port` و`--host` و`--root`؛ فمثلًا للإشارة إلى مساحة عمل أخرى:
`pnpm serve -- --root /path/to/workspace`.

## ماذا في الداخل

### هيكل مساحة العمل

يمنح وكيل الذكاء الاصطناعي مجموعة أدلة ذات أماكن ثابتة لكل شيء، ليبدأ العمل فورًا. سياق الذكاء
الاصطناعي يعيش في `.agents/` (الإنجليزية، JSON/YAML)، ومرآة مقروءة للبشر تعيش في `.users/`
(الكورية، Markdown). هذه المرآة جزئية وليست نسخة كاملة — فهي تحمل المستندات التي يحتاج الإنسان
لقراءتها (فمثلًا المهارات أصلها في `.agents/skills/`، وبعضها فقط معكوس في `.users/skills/`).
للمهارات والبيانات والمشاريع مواضع مخصصة، فتبدو مساحة العمل بالشكل نفسه أيًا كانت الأداة التي
تفتحها.

### لوحة التحكم وAPI

تدير لوحة تحكم Next.js مساحة العمل بصريًا، ويدعمها خادم API من Fastify. يكشف API بيانات مساحة
العمل الوصفية (`/api/workspace`) وفهرس المهارات (`/api/skills`) وقراءة الملفات وكتابتها
(`/api/files`) وWebSocket يبث أحداث تغيير الملفات (`/api/ws`). وبفضل API يستطيع الوصول إلى
مساحة العمل برامج أخرى غير لوحة التحكم.

### نظام المهارات

تُجمَّع المهام المتكررة في مهارات قابلة لإعادة الاستخدام. تُعرَّف كل مهارة بملف واحد `SKILL.md`،
ويفحص خادم API مجلد `skills/` لبناء الفهرس. إذا خالفت مهارة واحدة الصيغة، أخطأ الفهرس كله
(fail-closed): فبدل تجاهل المهارة المعطوبة بصمت وتقديم الباقي، يُلزَم المشغّل بإصلاحها في الحال.
وهو خيار مقصود لمنع شحن فهرس ناقص عن طريق الخطأ.

### القواعد والحوكمة الدنيا

حتى مساحة العمل التي تستخدمها وحدك تحتاج قواعد دنيا ما إن تمسّها الذكاء الاصطناعي والأتمتة. يفصل
Naia ADK بين `read` و`write` و`execute` و`publish` كاهتمامات متميزة، ويلحق بكل مستند مستوى
إفصاح. الأعمال صعبة التراجع — تغييرات الإنتاج ومعالجة الأسرار والادعاءات العامة — تُفصَل عن
التحريرات المحلية العادية وتُمرَّر عبر بوابات اعتماد.

للإفصاح أربع درجات. `public` آمن للشحن كما هو إلى موقع عام أو مستودع مفتوح المصدر؛ `controlled`
يمكن مشاركته خارجيًا بعد المراجعة؛ `internal` يبقى داخل مساحة العمل؛ `confidential` يغطي المواد
الحساسة مثل العقود وبيانات الاعتماد والبيانات الشخصية. تعيش بيانات الاعتماد عادة خارج git، لكنها
من حيث الدرجة تظل `confidential`.

> **إلزام عقد الجلسة معطّل في هذا الإصدار.** علامة `.claude/no-harness` مُثبتة في المستودع، فلا
> تحجب بوابة عقد الجلسة شيئًا. وعند تفعيلها تُحجَب الجلسة بلا عقد عن كل أوامر shell المُغيّرة —
> بما فيها `npm test` — فلا يستطيع المستنسَخ الجديد حتى تشغيل حزمة اختباراته. وقد فُتح مسار تحرير
> الملفات للسبب نفسه؛ أما مسار shell فلم يُعامَل بعد بالمثل. وحرّاس الدفع القسري وgit المدمّر
> والنشر والمراسلة الخارجية لا تتأثر وتستمر في العمل. يُتتبَّع التقدم في
> [#34](https://github.com/nextain/naia-template-project/issues/34)، والتفاصيل في
> `.claude/no-harness`. يصف قسم حدود الجلسة في `AGENTS.md` التصميم المقصود لا سلوك التشغيل الحالي.

### محوّل LLM ‏(naia-anyllm)

للمزايا التي تحتاج الوصول إلى LLM، يُبنى المحوّل `naia-anyllm` داخليًا. يتصل عبر بوابة
[any-llm](https://github.com/nextain/any-llm)، أو مباشرة بمزودين مثل OpenAI وAnthropic وGoogle.
الافتراضي حساب Naia: ضع مفتاحًا صادرًا من [naia.nextain.io](https://naia.nextain.io) في متغير
البيئة `NAIA_KEY` لتستخدم رصيد حسابك فورًا. وبدون مفتاح يُصدِر خطأً قبل أي استدعاء مدفوع.
لتبديل المزود أو النماذج انسخ
[`.agents/context/llm-config.yaml.example`](.agents/context/llm-config.yaml.example)، واحتفظ
بمفاتيح API في متغيرات البيئة أو مخزن مفاتيح نظام التشغيل لا في ملف الإعدادات. يسجّل
`naia-settings/llm.json` المرجع `apiKeyRef: "NAIA_KEY"` فقط وليس قيمة المفتاح أبدًا. وإذا احتاجت
نسخة شخصية إلى نسخ احتياطي طويل الأمد، فاستخدم الخزنة المشفرة بـ age في `data-private/key/` (انظر
[`.env.example`](.env.example)).

لسرد النماذج المدعومة وأسعارها الحالية، ولترجمة ملفات PDF الطويلة، استخدم مهارة `translate-doc`.
البحث عن النماذج والأسعار يعمل بلا مفتاح؛ والترجمة تعرض التكلفة التقديرية أولًا ويمكن أن تُستأنف
من حيث توقفت.

## لماذا بُني هكذا

### الصيغة هي العقد

قلب Naia ADK ليس أداة بعينها بل **صيغة**. فتخطيط الأدلة (`.agents/` و`.users/` و`skills/` و`data-*/`)
ومخططات الملفات (`agents-rules.json` و`SKILL.md`) اتفاق ثابت، وأي أداة تقرأ هذا الاتفاق تستطيع
استهلاك مساحة العمل نفسها. يقرأ Claude Code وopencode وCodex وnaia-agent مساحة العمل نفسها دون أن
يضمّن أحدها شيفرة الآخر. فيمكنك تبديل الأدوات أو المزج بين عدة منها، وتبقى مساحة العمل عاملة.

وإنفاذ القواعد نفسه محايد للأدوات أيضًا. فالنواة المحايدة للمضيف (`.agents/hooks/core/`)
والسياسات (`.agents/hooks/policies/`) تقودان خطافات Claude Code وامتداد pi بالقواعد نفسها.

### قاعدة شخصية قبل أن تكبر إلى فريق

Naia ADK أحادي المستخدم حصرًا، للاستعمال الشخصي. المخططات التنظيمية للشركات وقواعد المستأجرين
وسلاسل التفويض للاعتماد تنتمي إلى طبقة أعلى. وما يقدمه لك هو مكان واحد لتدوين انضباط السياق قبل أن
تكبر مساحة العمل إلى حجم فريق أو شركة.

وعندما تحتاج تعاون الفريق والمعرفة المشتركة، توسّع إلى
[Naia Business ADK](https://nextain.io/adk). يوسّع هذا الامتداد خط الأساس إلى حوكمة الأصول
والعمليات والأذونات، ويضيف ملكية الفريق والاعتمادات المفوّضة.

### سلسلة النسخ

صُمم Naia ADK ليُنسَخ ويصبح خاصتك. ينسخ الأفراد `naia-adk` مباشرة؛ أما المنظمات فتمر عبر
`naia-business-adk` لاستحداث مساحات عمل الشركة والأعضاء.

```
naia-adk                  ← قاعدة شخصية (عامة، Apache 2.0)
  └── {org}-adk           ← نسخة المنظمة: بيانات الشركة + وحدات الأعمال الفرعية
        └── {user}-adk    ← نسخة شخصية: بيانات شخصية + وحدات المشاريع الفرعية
```

السلسلة الفعلية في Nextain تسير
`naia-adk → naia-business-adk → nextain-adk → alpha-adk`.

## البنية

ينقسم المستودع إلى شيفرة التشغيل (`packages/`) والقواعد والسياق (`.agents/` و`.users/`)
والمهارات (`skills/` و`.agents/skills/`) وأدلة البيانات التي تملؤها كل نسخة.

| الدليل | الغرض |
|-----------|---------|
| `.agents/` | سياق الذكاء الاصطناعي (الإنجليزية، JSON/YAML) — المصدر الوحيد للحقيقة للقواعد |
| `.users/` | مرآة مقروءة للبشر (الكورية، Markdown) |
| `.claude/` | إعداد Claude Code والخطافات وروابط المهارات الرمزية |
| `skills/` | مهارات التشغيل/زمن التنفيذ (يقدّمها API لوحة التحكم) |
| `scripts/` | سكربتات مساعدة |
| `templates/` | قوالب المستندات |
| `docs/` | مستندات البنية ومواصفات التصميم |
| `packages/` | حزم التشغيل (مساحة عمل pnpm) |

### حزم التشغيل (packages/، 10 حزم)

ثلاث منها برامج عاملة فعلًا؛ والباقي حزم نحيفة تعرّف الصيغ والمواصفات.

- `core` — المحرك الذي يفسّر مساحة العمل والمهارات.
- `server` — API من REST/WebSocket على Fastify.
- `dashboard` — واجهة لوحة التحكم على Next.js.
- `skill-spec` — عقد صيغة المهارات المحايد للأدوات (`SkillDescriptor` و`SkillLoader`).
- `skills-builtin` — فهرس المهارات العامة.
- `openclaw-compat` — أداة تنقل مهارات OpenClaw إلى صيغة naia.
- `persona` — مواصفة اصطلاح موجّه النظام.
- `process` — مواصفة أنماط سير العمل (مراجعة → قرار → تنفيذ، والتطوير الموجه بالقضايا
  وهكذا).
- `naia-anyllm` — محوّل LLM لبوابة any-llm / المزودين المباشرين.
- `artifacts-spec` — المخطط المعياري لمخرجات الأذونات (RBAC) ودورة حياة التطوير
  (SDLC). يعرّف 15 نوعًا من المخرجات بصيغة JSON Schema ويحدد لكل نوع ما إذا كان المثيل
  مُتتبَّعًا في git أم محصورًا بالجلسة.

### أدلة البيانات (مُتجاهَلة من git، تُملأ لكل نسخة)

هذه الأربعة لا تُثبَّت أبدًا. من ينسخ المستودع يضع فيها بياناته.

| الدليل | النطاق | المحتوى |
|-----------|-------|---------|
| `data-company/` | الشركة | مستندات الشركة ومواردها المشتركة |
| `data-teams/` | الفريق | مستندات الفرق (الاستراتيجية والمحاسبة إلخ) |
| `data-private/` | شخصي | بيانات شخصية وملفات env ومستندات خاصة |
| `projects/` | شخصي | مستودعات المشاريع (وحدات فرعية) |

### شجرتا مهارات

تعيش المهارات في مكانين، ويستهلكهما طرفان مختلفان.

- `.agents/skills/` — مهارات مساعدة الذكاء الاصطناعي وسير العمل. يستخدمها Claude Code عبر الرابط
  الرمزي `.claude/skills/`. وتشمل المراجعة (`review-pass`) والتحقق (`verify-implementation`) ودمج
  شجرة العمل (`merge-worktree`) واستخراج المستندات (`read-doc`) ومهارات الأعمال مثل براءات
  الاختراع وحقوق النشر والرواتب، وغيرها مثل `finetune-persona` و`secret-vault` و`youtube-upload`.
- `skills/` — مهارات التشغيل/زمن التنفيذ. يفحص خادم API الملفات `skills/**/SKILL.md` ويقدمها
  للوحة التحكم. وتشمل إرسال البريد والرسائل والتنبيهات وإدارة القنوات ومراقبة الخدمات والويب
  وتوليد المستندات؛ ويحمل `skills/business/` مهارات المنظمة مثل `press-release`.

القائمة الأدق هي فهرس المهارات في لوحة التحكم. كما يُحفَظ جدول نصي في
[AGENTS.en.md](AGENTS.en.md#skills).

## البدء

### شخصي

1. انسخ `naia-adk` إلى حسابك (خاص إن أمكن).
2. استنسخه: `git clone https://github.com/YOUR-USER/your-adk.git && cd your-adk`
3. أضف المصدر الأعلى: `git remote add upstream https://github.com/nextain/naia-template-project.git`
4. أنشئ أدلة البيانات: `mkdir -p data-private projects`
5. أضف المشاريع واضبط `.agents/` وابدأ العمل.
6. إذا استخدمت موارد حساب Naia فعيّن `NAIA_KEY` متغيرًا للبيئة.
7. زامِن دوريًا: `git fetch upstream && git merge upstream/main`

### للشركات

1. [تواصل معنا](https://nextain.io/contact) للوصول إلى `naia-business-adk`.
2. انسخ `naia-business-adk` بشكل خاص إلى حساب المنظمة ثم استنسخه.
3. أضف المصدر الأعلى: `git remote add upstream https://github.com/nextain/naia-business-adk.git`
4. املأ بيانات الشركة ووحدات المشاريع الفرعية: `mkdir -p data-company projects`،
   `git submodule add <repo> projects/<name>`
5. ينسخ كل عضو ADK المنظمة مرة أخرى كمساحة عمل شخصية.

### تكامل Naia Shell ‏(اختياري)

إذا استخدمت تطبيق سطح المكتب [Naia Shell](https://github.com/nextain/naia-shell) فوجّه مسار مساحة
العمل فيه إلى دليل ADK الخاص بك. تُقدَّم المهارات والبيانات عبر API.

## المساهمة

اكتب القضايا وطلبات السحب والمناقشات باللغة التي تريحك؛ فالذكاء الاصطناعي يوسّط التواصل. وحافظ
فقط على سجل git (الالتزامات والسياق والمخرجات المشتركة) بالإنجليزية. للعملية الكاملة والقواعد انظر
[CONTRIBUTING.md](CONTRIBUTING.md). التطوير افتراضيًا موجَّه بالقضايا؛ والتدفق المفصّل يعيش في
[AGENTS.en.md](AGENTS.en.md) و[`.agents/workflows/`](.agents/workflows/).

## خارطة الطريق

التالي مخطط له، وليس مزية تعمل اليوم.

- **ذرات المعرفة** — سياق اليوم قائم على الملفات، فإيجاد معلومة واحدة يستلزم تحميل الملف كله
  وإهدار الرموز. الفكرة تكسير السياق إلى أصغر وحدات ذات معنى وربطها بالوسوم واستخراج القطعة
  المطلوبة بدقة. ويكون الوصول عبر CLI أو MCP ليبقى محايدًا للأدوات.
