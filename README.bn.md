# Naia ADK

**AI কোডিং এজেন্টদের কাজের জন্য আগে থেকে গুছিয়ে রাখা ওয়ার্কস্পেস কাঠামো।**

Claude Code বা Codex-এর মতো AI কোডিং টুল ব্যবহার করতে গেলে প্রতিটি টুল নিয়ম ফাইল
একেক জায়গায় রাখে, আর «এই নথি কি প্রকাশ করা যাবে?» বা «স্কিল কোথায় থাকবে?» জাতীয়
প্রশ্নের উত্তর দেওয়া হয় তাৎক্ষণিকভাবে। Naia ADK সেই কঙ্কাল আগেই বসিয়ে দেয়। নতুন
ল্যাপটপে যেমন ডেভেলপমেন্ট পরিবেশ সাজিয়ে নেন, তেমনি AI এজেন্টকেও শুরুতেই একটা গোছানো
ডেস্ক ধরিয়ে দেয়। সঙ্গে একটা ড্যাশবোর্ডও আছে, যাতে ওয়ার্কস্পেসের অবস্থা এক নজরে দেখা যায়।

## ৫ মিনিটে চালু করুন

**Node 22+** এবং **pnpm 9+** লাগবে।

```bash
pnpm install    # ওয়ার্কস্পেসের ডিপেন্ডেন্সি ইনস্টল করুন
pnpm dev        # API সার্ভার (:3141) ও ড্যাশবোর্ড (:3142) একসঙ্গে চালান
```

ড্যাশবোর্ড দেখতে ব্রাউজারে `http://localhost:3142` খুলুন। তিনটি জিনিস সঙ্গে সঙ্গে চোখে পড়ে:

- **ওয়ার্কস্পেস** — প্রজেক্ট ও সাবমডিউল, ফাইল ট্রি, এবং প্রতিটি আইটেমের
  প্রকাশ-মাত্রা।
- **স্কিল ক্যাটালগ** — এই ওয়ার্কস্পেসে নিবন্ধিত স্কিলের তালিকা ও তাদের
  বিষয়বস্তু।
- **সেটিংস / পর্যবেক্ষণ** — সার্ভার কনফিগারেশন, ক্লায়েন্ট অবস্থা, ডেটা ডিরেক্টরি।

ড্যাশবোর্ড `/api/*` অনুরোধগুলো 3141 পোর্টের API সার্ভারে পাঠিয়ে দেয়। শুধু একটা চালাতে
চাইলে `pnpm dev:server` (→ 3141) বা `pnpm dev:dashboard` (→ 3142) ব্যবহার করুন। লঞ্চার
স্ক্রিপ্ট `./start.sh` (Linux/macOS) ও `start.bat` (Windows) দুটোই `pnpm dev` চালায়। সার্ভার
CLI `--port`, `--host` ও `--root` নেয়; যেমন অন্য ওয়ার্কস্পেস দেখাতে হলে
`pnpm serve -- --root /path/to/workspace` লিখুন।

## ভেতরে কী আছে

### ওয়ার্কস্পেস কাঠামো

AI এজেন্ট যাতে সঙ্গে সঙ্গে কাজ শুরু করতে পারে, সেজন্য নির্দিষ্ট জায়গাসহ একগুচ্ছ ডিরেক্টরি
দেওয়া হয়েছে। AI-এর পড়ার প্রসঙ্গ থাকে `.agents/`-এ (ইংরেজি, JSON/YAML), আর মানুষের পড়ার
আয়না থাকে `.users/`-এ (কোরীয়, Markdown)। এই আয়না আংশিক, পূর্ণ অনুলিপি নয় — এতে সেই
নথিগুলোই থাকে যা মানুষের পড়া দরকার (যেমন স্কিলের আদি উৎস `.agents/skills/`, আর তার কিছু
অংশ `.users/skills/`-এ প্রতিফলিত)। স্কিল, ডেটা ও প্রজেক্ট — সবকিছুর নির্ধারিত জায়গা আছে,
তাই যে টুল দিয়েই খুলুন, ওয়ার্কস্পেস একই রকম দেখায়।

### ড্যাশবোর্ড ও API

Next.js ড্যাশবোর্ড ওয়ার্কস্পেসকে চোখে দেখে পরিচালনা করে, পেছনে থাকে Fastify API সার্ভার। API
প্রকাশ করে ওয়ার্কস্পেস মেটাডেটা (`/api/workspace`), স্কিল ক্যাটালগ (`/api/skills`), ফাইল
পড়া-লেখা (`/api/files`), এবং ফাইল বদলের ঘটনা সরাসরি পাঠানো WebSocket (`/api/ws`)। এই API-এর
সুবাদে ড্যাশবোর্ড ছাড়া অন্য প্রোগ্রামও ওয়ার্কস্পেসে পৌঁছাতে পারে।

### স্কিল ব্যবস্থা

পুনরাবৃত্ত কাজগুলো পুনর্ব্যবহারযোগ্য স্কিলে গুছিয়ে রাখা হয়। প্রতিটি স্কিল ঠিক একটি `SKILL.md`
দিয়ে সংজ্ঞায়িত, আর API সার্ভার `skills/` স্ক্যান করে ক্যাটালগ বানায়। একটা স্কিলও ধরন
ভাঙলে পুরো ক্যাটালগ ভুল তোলে (fail-closed): ভাঙা স্কিল চুপচাপ বাদ দিয়ে বাকিটা পরিবেশন না
করে অপারেটরকে ঘটনাস্থলেই ঠিক করতে বাধ্য করা হয়। অসম্পূর্ণ ক্যাটালগ ভুল করে শিপ করা ঠেকাতে
এটা সচেতন পছন্দ।

### নিয়ম ও সর্বনিম্ন পরিচালনা

একা ব্যবহার করা ওয়ার্কস্পেসেও ন্যূনতম নিয়ম লাগে, যেই AI ও অটোমেশন তাতে হাত দেয়। Naia ADK
`read`, `write`, `execute` ও `publish`-কে আলাদা আলাদা বিষয় হিসেবে ভাগ করে, আর প্রতিটি
নথিতে প্রকাশ-মাত্রা লাগায়। ফেরানো কঠিন কাজ — প্রোডাকশন পরিবর্তন, গোপন তথ্য নাড়াচাড়া,
জনসমক্ষে ঘোষণা — সাধারণ স্থানীয় সম্পাদনা থেকে আলাদা করে অনুমোদন গেট দিয়ে পার করা হয়।

প্রকাশের মাত্রা চারটি। `public` প্রকাশ্য সাইট বা ওপেনসোর্স রেপোতে যেমন আছে তেমন পাঠানো নিরাপদ;
`controlled` পর্যালোচনার পর বাইরে ভাগ করা যায়; `internal` ওয়ার্কস্পেসের ভেতরেই থাকে;
`confidential` সংবেদনশীল বিষয় ঢাকে, যেমন চুক্তি, পরিচয়পত্র ও ব্যক্তিগত তথ্য। পরিচয়পত্র
সাধারণত git-এর বাইরে থাকে, তবু মাত্রা অনুযায়ী সেগুলো `confidential`।

> **এই রিলিজে সেশন-চুক্তি প্রয়োগ বন্ধ আছে।** `.claude/no-harness` চিহ্ন কমিট করা আছে, তাই
> সেশন-চুক্তি গেট কিছুই আটকায় না। চালু করলে চুক্তিহীন সেশন প্রতিটি পরিবর্তনকারী শেল কমান্ডে
> আটকাবে — `npm test` সহ — ফলে নতুন ক্লোন নিজের টেস্ট স্যুটই চালাতে পারবে না। ফাইল সম্পাদনার
> পথ একই কারণে আগেই খুলে দেওয়া হয়েছে; শেল পথে এখনো সেই আচরণ আসেনি। ফোর্স-পুশ, ধ্বংসাত্মক
> git, ডিপ্লয় ও বহির্গামী বার্তা প্রহরী এর আওতামুক্ত, চলতে থাকে। অগ্রগতি
> [#34](https://github.com/nextain/naia-template-project/issues/34)-এ অনুসরণ করা হয়, বিস্তারিত
> `.claude/no-harness`-এ। `AGENTS.md`-এর সেশন সীমানা অংশ উদ্দেশ্য-নকশা বর্ণনা করে, বর্তমান
> রানটাইম আচরণ নয়।

### LLM অ্যাডাপ্টার (naia-anyllm)

LLM-এর কাছে পৌঁছাতে হয় এমন ফিচারের জন্য `naia-anyllm` অ্যাডাপ্টার ভেতরেই বানানো। এটি
[any-llm](https://github.com/nextain/any-llm) গেটওয়ের মধ্য দিয়ে, অথবা OpenAI, Anthropic ও
Google-এর মতো প্রোভাইডারে সরাসরি যুক্ত হয়। ডিফল্ট Naia অ্যাকাউন্ট: [naia.nextain.io](https://naia.nextain.io)
থেকে ইস্যু করা কী `NAIA_KEY` পরিবেশ ভেরিয়েবলে রাখলেই অ্যাকাউন্ট ক্রেডিট সঙ্গে সঙ্গে
ব্যবহার করা যায়। কী না থাকলে যেকোনো অর্থপ্রদানকারী কলের আগেই ভুল তোলে। প্রোভাইডার বা মডেল
বদলাতে চাইলে [`.agents/context/llm-config.yaml.example`](.agents/context/llm-config.yaml.example)
অনুলিপি করে ব্যবহার করুন, আর API কী কনফিগ ফাইলে নয়, পরিবেশ ভেরিয়েবল বা OS-এর কীস্টোরে
রাখুন। `naia-settings/llm.json`-এ শুধু `apiKeyRef: "NAIA_KEY"` লেখা থাকে, কী-এর মান কখনো
নয়। ব্যক্তিগত ফোর্কে দীর্ঘমেয়াদি ব্যাকআপ লাগলে `data-private/key/`-এর age-এনক্রিপ্টেড ভল্ট
ব্যবহার করুন (দেখুন [`.env.example`](.env.example))।

সমর্থিত মডেল ও বর্তমান দাম দেখতে, আর লম্বা PDF অনুবাদ করতে `translate-doc` স্কিল ব্যবহার
করুন। মডেল-দাম অনুসন্ধান কী ছাড়াই চলে; অনুবাদ আগে আনুমানিক খরচ দেখায় এবং থামা জায়গা থেকে
আবার শুরু হতে পারে।

## কেন এভাবে বানানো

### ধরনই চুক্তি

Naia ADK-এর প্রাণ কোনো নির্দিষ্ট টুল নয়, বরং **ধরন**। ডিরেক্টরি বিন্যাস (`.agents/`,
`.users/`, `skills/`, `data-*/`) ও ফাইল স্কিমা (`agents-rules.json`, `SKILL.md`) স্থির চুক্তি,
আর যে টুল সেই চুক্তি পড়তে পারে সে-ই একই ওয়ার্কস্পেস ব্যবহার করতে পারে। Claude Code, opencode,
Codex ও naia-agent একে অন্যের কোড না ঢুকিয়েই একই ওয়ার্কস্পেস পড়ে। তাই টুল বদলান বা একাধিক
মিশিয়ে চালান, ওয়ার্কস্পেস চলতেই থাকে।

নিয়ম প্রয়োগও টুল-নিরপেক্ষ। হোস্ট-নিরপেক্ষ কোর (`.agents/hooks/core/`) ও নীতি
(`.agents/hooks/policies/`) একই নিয়মে Claude Code হুক ও pi এক্সটেনশন দুটোই চালায়।

### দলে বাড়ার আগের ব্যক্তিগত ভিত্তি

Naia ADK কঠোরভাবে একক-ব্যবহারকারী, ব্যক্তিগত ব্যবহারের জন্য। কোম্পানির সাংগঠনিক চার্ট,
টেনান্ট নিয়ম ও অর্পিত অনুমোদন শৃঙ্খলা ওপরের স্তরের কাজ। বরং ওয়ার্কস্পেস দল বা কোম্পানি
আকারে বাড়ার আগে প্রসঙ্গ-শৃঙ্খলা কোথায় লিখবেন, সেই একটা জায়গা দেয়।

দলীয় সহযোগিতা ও ভাগ করা জ্ঞান দরকার হলে
[Naia Business ADK](https://nextain.io/adk)-তে সম্প্রসারিত করুন। এই সম্প্রসারণ ভিত্তিরেখাকে
সম্পদ-, প্রক্রিয়া- ও অনুমতি-পরিচালনায় প্রসারিত করে, আর দলীয় মালিকানা ও অর্পিত অনুমোদন যোগ করে।

### ফোর্ক শৃঙ্খলা

Naia ADK ফোর্ক করে নিজের করে নেওয়ার জন্যই। ব্যক্তিরা `naia-adk` সরাসরি ফোর্ক করেন; সংস্থাগুলো
`naia-business-adk` হয়ে কোম্পানি ও সদস্য ওয়ার্কস্পেস তৈরি করে।

```
naia-adk                  ← ব্যক্তিগত ভিত্তি (প্রকাশ্য, Apache 2.0)
  └── {org}-adk           ← সংস্থা ফোর্ক: কোম্পানি ডেটা + ব্যবসায়িক সাবমডিউল
        └── {user}-adk    ← ব্যক্তিগত ফোর্ক: ব্যক্তিগত ডেটা + প্রজেক্ট সাবমডিউল
```

Nextain-এর আসল শৃঙ্খলা চলে `naia-adk → naia-business-adk → nextain-adk → alpha-adk`।

## গঠন

সংগ্রহশালা ভাগ হয়েছে রানটাইম কোড (`packages/`), নিয়ম ও প্রসঙ্গ (`.agents/`, `.users/`),
স্কিল (`skills/`, `.agents/skills/`), এবং প্রতিটি ফোর্ক ভরে এমন ডেটা ডিরেক্টরিতে।

| ডিরেক্টরি | উদ্দেশ্য |
|-----------|---------|
| `.agents/` | AI-এর পড়ার প্রসঙ্গ (ইংরেজি, JSON/YAML) — নিয়মের একক সত্য উৎস |
| `.users/` | মানুষের পড়ার আয়না (কোরীয়, Markdown) |
| `.claude/` | Claude Code কনফিগ, হুক, স্কিল সিমলিংক |
| `skills/` | পরিচালন/রানটাইম স্কিল (ড্যাশবোর্ড API পরিবেশন করে) |
| `scripts/` | সহায়ক স্ক্রিপ্ট |
| `templates/` | নথি টেমপ্লেট |
| `docs/` | স্থাপত্য নথি, নকশা স্পেসিফিকেশন |
| `packages/` | রানটাইম প্যাকেজ (pnpm ওয়ার্কস্পেস) |

### রানটাইম প্যাকেজ (packages/, মোট ১০টি)

তিনটি আসলে চলা প্রোগ্রাম; বাকিগুলো ধরন ও স্পেসিফিকেশন বলা পাতলা প্যাকেজ।

- `core` — ওয়ার্কস্পেস ও স্কিল পার্স করা ইঞ্জিন।
- `server` — Fastify-ভিত্তিক REST/WebSocket API।
- `dashboard` — Next.js ড্যাশবোর্ড UI।
- `skill-spec` — টুল-নিরপেক্ষ স্কিল ধরন চুক্তি (`SkillDescriptor`, `SkillLoader`)।
- `skills-builtin` — সাধারণ স্কিল ক্যাটালগ।
- `openclaw-compat` — OpenClaw স্কিল naia ধরনে নেওয়ার মাইগ্রেশন টুল।
- `persona` — সিস্টেম-প্রম্প্ট রীতি স্পেসিফিকেশন।
- `process` — ওয়ার্কফ্লো ধরন স্পেসিফিকেশন (পর্যালোচনা → সিদ্ধান্ত → সম্পাদন, ইস্যু-চালিত
  উন্নয়ন ইত্যাদি)।
- `naia-anyllm` — any-llm গেটওয়ে / সরাসরি-প্রোভাইডার LLM অ্যাডাপ্টার।
- `artifacts-spec` — অনুমতি (RBAC) ও উন্নয়ন জীবনচক্র (SDLC) শিল্পকর্মের মান স্কিমা। ১৫
  ধরনের শিল্পকর্ম JSON Schema-তে সংজ্ঞায়িত করে এবং প্রতিটির জন্য বলে ইনস্ট্যান্স git-এ
  ট্র্যাক হয় না সেশন-সীমিত।

### ডেটা ডিরেক্টরি (gitignore-কৃত, প্রতি ফোর্কে ভরা)

এই চারটি কখনো কমিট হয় না। যিনি রেপো ফোর্ক করেন তিনি নিজের ডেটা রাখেন।

| ডিরেক্টরি | পরিধি | বিষয়বস্তু |
|-----------|-------|---------|
| `data-company/` | কোম্পানি | কোম্পানিব্যাপী নথি, ভাগ করা সম্পদ |
| `data-teams/` | দল | দলীয় নথি (কৌশল, হিসাব ইত্যাদি) |
| `data-private/` | ব্যক্তিগত | ব্যক্তিগত ডেটা, env ফাইল, ব্যক্তিগত নথি |
| `projects/` | ব্যক্তিগত | প্রজেক্ট রেপো (সাবমডিউল) |

### দুটি স্কিল বৃক্ষ

স্কিল দুই জায়গায় থাকে, দুই পক্ষ ব্যবহার করে।

- `.agents/skills/` — AI সহায়তা ও ওয়ার্কফ্লো স্কিল। Claude Code `.claude/skills/` সিমলিংক
  দিয়ে ব্যবহার করে। পর্যালোচনা (`review-pass`), যাচাইকরণ (`verify-implementation`),
  ওয়ার্কট্রি মার্জ (`merge-worktree`), নথি নিষ্কাশন (`read-doc`), পেটেন্ট/কপিরাইট/বেতনের মতো
  ব্যবসায়িক স্কিল, আর `finetune-persona`, `secret-vault`, `youtube-upload`-এর মতো অন্যান্য।
- `skills/` — পরিচালন/রানটাইম স্কিল। API সার্ভার `skills/**/SKILL.md` স্ক্যান করে
  ড্যাশবোর্ডকে দেয়। এতে ইমেল/SMS/বিজ্ঞপ্তি পাঠানো, চ্যানেল পরিচালনা, পরিষেবা ও ওয়েব
  পর্যবেক্ষণ, আর নথি তৈরি আছে; `skills/business/`-এ সংস্থার স্কিল যেমন `press-release`।

সবচেয়ে নির্ভুল তালিকা ড্যাশবোর্ডের স্কিল ক্যাটালগ। পাঠ্য টেবিলও
[AGENTS.en.md](AGENTS.en.md#skills)-এ রাখা আছে।

## শুরু

### ব্যক্তিগত

1. `naia-adk` নিজের অ্যাকাউন্টে ফোর্ক করুন (পারলে প্রাইভেট)।
2. ক্লোন করুন: `git clone https://github.com/YOUR-USER/your-adk.git && cd your-adk`
3. আপস্ট্রিম যোগ করুন: `git remote add upstream https://github.com/nextain/naia-template-project.git`
4. ডেটা ডিরেক্টরি বানান: `mkdir -p data-private projects`
5. প্রজেক্ট যোগ করুন, `.agents/` সাজান, আর কাজ শুরু করুন।
6. Naia অ্যাকাউন্ট সম্পদ ব্যবহার করলে `NAIA_KEY` পরিবেশ ভেরিয়েবলে সেট করুন।
7. নিয়মিত সিঙ্ক করুন: `git fetch upstream && git merge upstream/main`

### কোম্পানি

1. `naia-business-adk` অ্যাক্সেসের জন্য [যোগাযোগ করুন](https://nextain.io/contact)।
2. `naia-business-adk` সংস্থা অ্যাকাউন্টে প্রাইভেট ফোর্ক করে ক্লোন করুন।
3. আপস্ট্রিম যোগ করুন: `git remote add upstream https://github.com/nextain/naia-business-adk.git`
4. কোম্পানি ডেটা ও প্রজেক্ট সাবমডিউল ভরুন: `mkdir -p data-company projects`,
   `git submodule add <repo> projects/<name>`
5. প্রতিটি সদস্য সংস্থা ADK আবার ফোর্ক করে ব্যক্তিগত ওয়ার্কস্পেস বানায়।

### Naia Shell সংযোগ (ঐচ্ছিক)

[Naia Shell](https://github.com/nextain/naia-shell) ডেস্কটপ অ্যাপ ব্যবহার করলে ওয়ার্কস্পেস পথ
আপনার ADK ডিরেক্টরিতে দেখান। স্কিল ও ডেটা API-এর মাধ্যমে পরিবেশিত হয়।

## রোডম্যাপ

নিচে পরিকল্পিত, আজ কাজ করে এমন ফিচার নয়।

- **জ্ঞান পরমাণু** — আজকের প্রসঙ্গ ফাইল-ভিত্তিক, ফলে এক টুকরো তথ্য খুঁজতেও পুরো ফাইল লোড
  করতে হয় আর টোকেন নষ্ট হয়। ভাবনা হলো প্রসঙ্গকে ক্ষুদ্রতম অর্থবহ এককে ভেঙে ট্যাগে জোড়া, আর
  ঠিক দরকারি অংশটুকু তোলা। প্রবেশ CLI বা MCP দিয়ে হবে, যাতে টুল-নিরপেক্ষ থাকে।
