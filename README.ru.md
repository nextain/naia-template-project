# Naia ADK

**Заранее наведённый каркас рабочего пространства для AI-кодирующих агентов.**

Когда пользуешься AI-инструментами для кодинга вроде Claude Code или Codex, у каждого инструмента
своё место для файлов правил, а вопросы «можно ли публиковать этот документ?» или «куда класть
скиллы?» решаются на ходу. Naia ADK раскладывает этот скелет заранее. Как на новом ноутбуке сначала
настраивают окружение для разработки, так и AI-агенту он сразу выдаёт прибранный стол. А ещё в
комплекте идёт дашборд, где состояние рабочего пространства видно с одного взгляда.

## Запуск за 5 минут

Нужны **Node 22+** и **pnpm 9+**.

```bash
pnpm install    # установка зависимостей рабочего пространства
pnpm dev        # одновременный запуск API-сервера (:3141) и дашборда (:3142)
```

Открой в браузере `http://localhost:3142`, и увидишь дашборд. Сразу видны три вещи:

- **Рабочее пространство** — проекты и субмодули, дерево файлов и уровень раскрытия каждого элемента.
- **Каталог скиллов** — список скиллов, зарегистрированных в этом пространстве, и их содержимое.
- **Настройки / мониторинг** — конфигурация сервера, состояние клиентов, каталоги данных.

Дашборд проксирует запросы `/api/*` на API-сервер на порту 3141. Чтобы запустить что-то одно,
используй `pnpm dev:server` (→ 3141) или `pnpm dev:dashboard` (→ 3142). Скрипты запуска
`./start.sh` (Linux/macOS) и `start.bat` (Windows) оба выполняют `pnpm dev`. CLI сервера принимает
`--port`, `--host` и `--root`; например, чтобы указать на другое пространство:
`pnpm serve -- --root /path/to/workspace`.

## Что внутри

### Каркас рабочего пространства

Он даёт AI-агенту набор каталогов с фиксированными местами, чтобы тот начинал работать сразу.
Контекст для AI живёт в `.agents/` (английский, JSON/YAML), а читаемое человеком зеркало — в
`.users/` (корейский, Markdown). Это зеркало частичное, не полная копия: в нём документы, которые
нужно читать человеку (например, скиллы каноничны в `.agents/skills/`, а в `.users/skills/`
отзеркалена лишь часть). У скиллов, данных и проектов есть назначенные места, поэтому пространство
выглядит одинаково, каким бы инструментом его ни открыли.

### Дашборд и API

Визуально пространством управляет дашборд на Next.js, а под ним работает API-сервер на Fastify. API
отдаёт метаданные пространства (`/api/workspace`), каталог скиллов (`/api/skills`), чтение/запись
файлов (`/api/files`) и WebSocket, который стримит события изменения файлов (`/api/ws`). Благодаря
этому API к пространству могут обращаться и другие программы, а не только дашборд.

### Система скиллов

Повторяющиеся задачи упаковываются в переиспользуемые скиллы. Каждый скилл определён одним файлом
`SKILL.md`, а API-сервер сканирует `skills/` и строит каталог. Если хотя бы один скилл нарушает
формат, весь каталог падает с ошибкой (fail-closed): вместо того чтобы молча выкинуть сломанный
скилл и отдать остальные, оператор вынужден чинить его на месте. Это осознанный выбор, чтобы не
отгрузить случайно неполный каталог.

### Правила и минимальное управление

Даже пространству, которым пользуешься в одиночку, нужны минимальные правила, как только его
касаются AI и автоматизация. Naia ADK разделяет `read`, `write`, `execute` и `publish` как разные
зоны ответственности и вешает на каждый документ уровень раскрытия. Труднообратимые действия —
продакшен-изменения, обращение с секретами, публичные заявления — отделены от обычных локальных
правок и идут через гейты согласования.

У раскрытия четыре уровня. `public` можно как есть выносить на публичный сайт или в
open-source-репозиторий; `controlled` можно делиться вовне после ревью; `internal` остаётся внутри
пространства; `confidential` покрывает чувствительное: договоры, учётные данные, персональные
данные. Учётные данные обычно живут вне git, но по уровню они всё равно `confidential`.

> **Принуждение сессионного контракта в этом релизе отключено.** Закоммичен маркер
> `.claude/no-harness`, поэтому гейт сессионного контракта ничего не блокирует. Если его включить,
> сессия без контракта будет заблокирована для любой мутирующей shell-команды — включая `npm test`,
> — так что свежий клон не сможет прогнать даже собственный тестовый набор. Путь редактирования
> файлов открыт по той же причине; shell-пути такого же послабления пока не получили. Гарды
> force-push, деструктивного git, деплоя и исходящих сообщений не затронуты и продолжают работать.
> Прогресс отслеживается в [#34](https://github.com/nextain/naia-template-project/issues/34),
> детали — в `.claude/no-harness`. Раздел про границы сессий в `AGENTS.md` описывает задуманный
> дизайн, а не текущее поведение рантайма.

### LLM-адаптер (naia-anyllm)

Для функций, которым нужно достучаться до LLM, встроен адаптер `naia-anyllm`. Он подключается через
шлюз [any-llm](https://github.com/nextain/any-llm) либо напрямую к провайдерам вроде OpenAI,
Anthropic и Google. По умолчанию — аккаунт Naia: положи ключ, выданный на
[naia.nextain.io](https://naia.nextain.io), в переменную окружения `NAIA_KEY`, и сразу пользуйся
кредитом аккаунта. Без ключа он упадёт с ошибкой до любого платного вызова. Чтобы сменить провайдера
или модели, скопируй [`.agents/context/llm-config.yaml.example`](.agents/context/llm-config.yaml.example),
а API-ключи держи в переменных окружения или в хранилище ключей ОС, а не в конфиге.
`naia-settings/llm.json` записывает только `apiKeyRef: "NAIA_KEY"`, но не само значение ключа. Если
личному форку нужно долгосрочное резервное хранение, используй age-шифрованный vault в
`data-private/key/` (см. [`.env.example`](.env.example)).

Для просмотра поддерживаемых моделей и актуальных цен, а также для перевода длинных PDF используй
скилл `translate-doc`. Просмотр моделей и цен работает без ключа; перевод сначала показывает
оценочную стоимость и умеет продолжать с места остановки.

## Почему устроено так

### Формат и есть контракт

Сердце Naia ADK — не конкретный инструмент, а **формат**. Раскладка каталогов (`.agents/`,
`.users/`, `skills/`, `data-*/`) и схемы файлов (`agents-rules.json`, `SKILL.md`) — это
фиксированная договорённость, и любой инструмент, умеющий её читать, может потреблять то же самое
пространство. Claude Code, opencode, Codex и naia-agent читают одно и то же пространство, не встраивая
код друг друга. Поэтому инструменты можно менять или мешать несколько, а пространство продолжает
работать.

И само принуждение правил не привязано к инструментам. Хостовно-нейтральное ядро
(`.agents/hooks/core/`) и политики (`.agents/hooks/policies/`) гонят одними и теми же правилами и
хуки Claude Code, и расширение pi.

### Личная база до того, как вырастет в командную

Naia ADK строго однопользовательский, для личного пользования. Оргструктуры компаний, правила
тенантов и цепочки делегированных согласований — слой выше. А он даёт одно место, где заранее
записать дисциплину контекста, пока пространство не выросло до масштаба команды или компании.

Когда понадобятся командная коллаборация и общие знания, расширься до
[Naia Business ADK](https://nextain.io/adk). Это расширение раздвигает baseline на управление
ассетами, процессами и правами, добавляет владение командой и делегированные согласования.

### Цепочка форков

Naia ADK задуман так, чтобы его форкали под себя. Люди форкают `naia-adk` напрямую; организации идут
через `naia-business-adk`, чтобы инстанцировать пространства компании и участников.

```
naia-adk                  ← личная база (публичная, Apache 2.0)
  └── {org}-adk           ← форк организации: данные компании + бизнес-субмодули
        └── {user}-adk    ← личный форк: личные данные + субмодули проектов
```

Реальная цепочка Nextain идёт `naia-adk → naia-business-adk → nextain-adk → alpha-adk`.

## Структура

Репозиторий делится на рантайм-код (`packages/`), правила и контекст (`.agents/`, `.users/`),
скиллы (`skills/`, `.agents/skills/`) и каталоги данных, которые заполняет каждый форк.

| Каталог | Назначение |
|-----------|---------|
| `.agents/` | Контекст для AI (английский, JSON/YAML) — единый источник правды правил |
| `.users/` | Читаемое человеком зеркало (корейский, Markdown) |
| `.claude/` | Конфиг Claude Code, хуки, симлинки скиллов |
| `skills/` | Операционные/рантайм-скиллы (отдаёт API дашборда) |
| `scripts/` | Утилитарные скрипты |
| `templates/` | Шаблоны документов |
| `docs/` | Документы архитектуры, проектные спеки |
| `packages/` | Рантайм-пакеты (pnpm-workspace) |

### Рантайм-пакеты (packages/, всего 10)

Три — реально работающие программы; остальные — тонкие пакеты, задающие форматы и спеки.

- `core` — движок, который парсит пространство и скиллы.
- `server` — REST/WebSocket API на Fastify.
- `dashboard` — UI дашборда на Next.js.
- `skill-spec` — инструментно-нейтральный контракт формата скиллов (`SkillDescriptor`,
  `SkillLoader`).
- `skills-builtin` — общий каталог скиллов.
- `openclaw-compat` — инструмент, мигрирующий скиллы OpenClaw в формат naia.
- `persona` — спека конвенции системных промптов.
- `process` — спека паттернов workflow (ревью → решение → исполнение, issue-driven разработка
  и т. д.).
- `naia-anyllm` — LLM-адаптер шлюза any-llm / прямых провайдеров.
- `artifacts-spec` — стандартная схема артефактов прав (RBAC) и жизненного цикла разработки
  (SDLC). Определяет 15 типов артефактов как JSON Schema и задаёт для каждого, отслеживается ли
  инстанс в git или ограничен сессией.

### Каталоги данных (gitignored, заполняются в каждом форке)

Эти четыре никогда не коммитятся. Тот, кто форкнул репозиторий, кладёт туда свои данные.

| Каталог | Охват | Содержимое |
|-----------|-------|---------|
| `data-company/` | Компания | Общекомпанейские документы, общие ресурсы |
| `data-teams/` | Команда | Документы команды (стратегия, учёт и т. д.) |
| `data-private/` | Личное | Личные данные, env-файлы, приватные документы |
| `projects/` | Личное | Репозитории проектов (субмодули) |

### Два дерева скиллов

Скиллы живут в двух местах, их потребляют разные стороны.

- `.agents/skills/` — скиллы AI-ассиста и workflow. Claude Code пользуется ими через симлинк
  `.claude/skills/`. Внутри ревью (`review-pass`), верификация (`verify-implementation`), слияние
  worktree (`merge-worktree`), извлечение документов (`read-doc`), бизнес-скиллы вроде
  патентов/копирайта/зарплаты и другие вроде `finetune-persona`, `secret-vault` и `youtube-upload`.
- `skills/` — операционные/рантайм-скиллы. API-сервер сканирует `skills/**/SKILL.md` и отдаёт их
  дашборду. Это отправка email/SMS/уведомлений, управление каналами, мониторинг сервисов и веба,
  генерация документов; в `skills/business/` лежат орг-скиллы вроде `press-release`.

Самый точный список — каталог скиллов в дашборде. Текстовая таблица также ведётся в
[AGENTS.en.md](AGENTS.en.md#skills).

## Начало работы

### Личное

1. Форкни `naia-adk` в свой аккаунт (по возможности приватно).
2. Клонируй: `git clone https://github.com/YOUR-USER/your-adk.git && cd your-adk`
3. Добавь upstream: `git remote add upstream https://github.com/nextain/naia-template-project.git`
4. Создай каталоги данных: `mkdir -p data-private projects`
5. Добавь проекты, настрой `.agents/` и начинай работать.
6. Если пользуешься ресурсами аккаунта Naia, выставь `NAIA_KEY` переменной окружения.
7. Регулярно синхронизируйся: `git fetch upstream && git merge upstream/main`

### Компания

1. Для доступа к `naia-business-adk` [свяжись с нами](https://nextain.io/contact).
2. Форкни `naia-business-adk` приватно в аккаунт организации, затем клонируй.
3. Добавь upstream: `git remote add upstream https://github.com/nextain/naia-business-adk.git`
4. Заполни данные компании и субмодули проектов: `mkdir -p data-company projects`,
   `git submodule add <repo> projects/<name>`
5. Каждый участник снова форкает орг-ADK как личное пространство.

### Интеграция Naia Shell (необязательно)

Если пользуешься десктопным приложением [Naia Shell](https://github.com/nextain/naia-shell), укажи
его путь к пространству на свой каталог ADK. Скиллы и данные отдаются через API.

## Участие

Пиши issues, PR и обсуждения на языке, на котором тебе удобно; AI модерирует общение. Только git-запись
(коммиты, контекст, общие артефакты) держи на английском. Полный процесс и правила см. в
[CONTRIBUTING.md](CONTRIBUTING.md). Разработка по умолчанию issue-driven; детальный поток живёт в
[AGENTS.en.md](AGENTS.en.md) и [`.agents/workflows/`](.agents/workflows/).

## Дорожная карта

Ниже — запланированное, а не то, что работает сегодня.

- **Атомы знаний** — сегодняшний контекст файл-based: чтобы найти один кусочек информации, приходится
  грузить весь файл и жечь токены. Идея — разбить контекст на минимальные осмысленные единицы,
  связать тегами и доставать ровно нужный кусочек. Доступ — через CLI или MCP, чтобы остаться
  инструментно-нейтральным.
